
ROS2 project
Owner: Moganesan. Private project.
Goal: build a safe ROS 2 Jazzy autonomous indoor drone stack from scratch (Raspberry Pi 5 companion, Ubuntu 24.04, Pixhawk + ArduPilot over MAVLink). Current scope: MAVLink bridge, state, optical flow via FCU EKF, camera, YOLO person detection, tracking, deterministic search/track mission, safety watchdog, LLM intent layer. Future only: VIO, SLAM, LiDAR, mapping.

Final goal is FULLY autonomous flight (2026-09-27): ROS must support pre-arm validation, mode, arm, takeoff to configured altitude with verification, mission, autonomous land, disarm, all through the safety layer. RC stays as manual override/emergency only. Do not design around RC-only arm/takeoff.

Hardware: Pixhawk TELEM1 (SERIAL1), MAVLink 2, ModemManager disabled. SERIAL1 baud changed by user to 921600 on 2026-09-29 (was 115200); Phase 8 release makes fcu_baud default 921600. ArduCopter 4.6.3. GPS removed (indoor). Battery 4S (user 2026-09-29), NOT yet connected on the bench: drone powered by USB only (2026-09-29). Flow sensor MTF-01 (optical flow + rangefinder; rangefinder reports via DISTANCE_SENSOR, device 1/88, reads 0.14 m on floor because of landing gear) on TELEM2 = SERIAL2 @115200. Camera: Zebronics USB. Pi 5 has active cooler.

Test area: home floor is tiles; user has a textured "mat" of 5+ cardboard boxes. Bench setup: drone sits on a table, tethered by the Pi power cable, cannot be moved around (2026-09-29).

Pi devices (user output 2026-09-28): TELEM1 = /dev/ttyAMA0 (also /dev/ttyAMA10 exists; no /dev/serial* symlinks, no ttyUSB/ttyACM); USB camera "HD camera" at /dev/video0 (+/dev/video1). Pi user is virtua, hostname viruta.

RC: RC6_OPTION=31 (motor emergency stop) set by user 2026-09-29 (was 17 AutoTune). Flight-mode switch includes STABILIZE, LOITER and GUIDED. Phase 4 test: switching TX off mid-run did not change RC state, likely receiver holds last values (failsafe not "no pulses"); flagged to user 2026-09-29. Node now also uses ArduPilot radio-failsafe flag.

No GPS means no home/EKF origin: with ARMING_CHECK=1, arming in LOITER is refused ("PreArm: AHRS: waiting for home"), STABILIZE arms fine (user 2026-09-29). Phase 8 sets the EKF origin from the Pi at startup (lat/lon in drone.yaml, city level) so GUIDED arming works without GPS.

Working style: phased, props-off bench testing by default, complete files, exact commands, "WHAT / WHY / COMMAND / EXPECTED / IF NOT" troubleshooting. Stop at checkpoints for user confirmation.
